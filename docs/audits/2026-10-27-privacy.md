# Privacy audit, 2026-10-27

Scope commit: `docs/as-built-data` at `f505948`. Report text below is unchanged from the auditor.


**The audit found confirmed privacy gaps in All Jobs, note authorship, and shared-company data propagation, plus the known shared search-criteria gap.** Ordinary access to explicitly owned jobs and experiences is scoped correctly; direct admin-only writes are guarded.

**Scope:** `docs/as-built-data` at `f505948`. No files changed, no product app started, and no vault mutations performed. Verification used source inspection and synthetic in-memory probes. **CONFIRMED** means the code path was verified, not that sensitive production records were inspected. **ASSUMED** identifies an unverified condition.

| `GET /api/jobs?view=universe` — All Jobs | Ownerless jobs; author-scoped notes; history | **high** | **CONFIRMED:** `careeros/vault.py:Owner.sees_in_universe` allows `self.owns(record) or not (record or {}).get(OWNER_FIELD)`. `careeros/web/pages/jobs.py:universe_context`, `board_context`, and `careeros/server.py:job_collection` return the complete job dictionaries, adding fields without removing `notes`, `note_list`, `history`, `custom`, or personal workflow fields. | Company collection/detail and company payloads embedded in job/experience/form/intake responses | Shared free-form fields | **medium** | **CONFIRMED:** `careeros/vault.py:_record_defaults` accepts company `custom`, `enrichment`, `sources`, `field_provenance`, `review_flags`, and `contact_email`. `reader_company` filters `note_list` and legacy `notes` only; arbitrary nested private text or user IDs in other fields remain visible. `careeros/server.py:company_api` correctly makes generic writes admin-only. | `POST /api/jobs/<identifier>/promote` | Copy from ownerless posting into a private job | **low** | **CONFIRMED:** `careeros/vault.py:add_job_to_board` copies every job-allowlisted field except `BOARD_COPY_EXCLUDED`. Flask’s automatic HEAD executes the handler with method `HEAD`; an in-memory framework probe confirmed the non-GET branch. With a suitable body, HEAD can save criteria, create/update records, or perform authentication/token actions. **Checked and found CLEAN**

The following are **CONFIRMED source checks**, subject to the specific findings above.

- **Explicitly owned jobs:** `GET /api/jobs` and `?view=board`; `GET/PUT/DELETE /api/jobs/<id>` including `?view=page`; POST `/enrich`, `/extract`, `/re-extract`, `/paste-description`, `/resolve`, `/resolve-review`; and both API/HTML taxonomy routes pass a session-derived owner to their first job lookup. Another user’s explicit owner ID produces the missing-record response. Evidence: `careeros/server.py:job_collection`, `job_api`, the corresponding action handlers; `careeros/web/pages/jobs.py:detail_context`, `taxonomy_context`, `taxonomy`; `careeros/vault.py:load_job`, `owned`.

- **Create, update, duplicate, and response paths:** intake stamps `owner.identifier` rather than accepting a payload owner; generic updates strip `owner_id`. Duplicate checking searches only `list_owned_jobs(root, owner)` and returns only that owner’s match. Intake company responses call `reader_company`, including failure responses. Evidence: `careeros/server.py:job_intake`, `job_api`; `careeros/dedupe.py:find_duplicate`, `duplicate_payload`. No generic job-creation endpoint exists alongside intake.

- **Promotion ownership and history:** `/promote` uses `load_universe_job`, so it cannot select another user’s explicitly owned job. A tester receives a new record stamped with their own owner ID; the source is unchanged. Repeat promotion checks the tester’s own duplicates. Notes and old history do not survive the copy. Evidence: `careeros/server.py:promote_job`; `careeros/vault.py:load_universe_job`, `add_job_to_board`, `_save_record`.

- **Experiences, including echoes:** GET/POST collection; GET/PUT/POST/DELETE detail; API new/edit forms; HTML new/edit forms; and `/link-company` all scope private reads. Create overwrites any submitted owner; updates remove it. Link/unlink responses contain the caller’s experience, not another user’s. Evidence: `careeros/server.py:experience_collection`, `_experience_payload`, `experience_api`, `experience_form_api`, `link_experience_company`; `careeros/web/pages/experiences.py:get`, `page_context`, `detail_context`, `form_context`, `form`.

- **Company-note endpoints and aggregation:** company reads filter notes by `Owner.owns_note`; non-admins also lose legacy free-text company notes. POST stamps the session author; PATCH accepts only title/body; PATCH/DELETE locate the note in the filtered view before loading the full company for preservation. Responses echo only the created/edited note. `/api/notes` combines owned jobs with filtered companies. Evidence: `careeros/server.py:NOTE_KINDS`, `create_note`, `note_api`, `_note_write_record`, `notes_api`; `careeros/vault.py:reader_company`, `edit_note`; `careeros/web/pages/notes.py:page_context`. Job-note endpoints first enforce job ownership; the generic-update authorship exception is reported above.

- **Counts, summaries, scans, and history:** board statistics use scoped job inputs; company directory counts use the reader’s universe, excluding other users’ explicitly owned jobs; company detail lists scoped jobs/experiences; taxonomy skill counts use owned experiences. Named and batch `/api/watch/scan` both scope the sweep and re-read, and return events only for that scope. Evidence: `careeros/web/pages/jobs.py:board_context`, `search_so_far`; `companies.py:page_context`, `detail_context`; `taxonomy.py:taxonomy_context`; `careeros/server.py:watch_scan`; `careeros/watcher.py:scan`. The shared rollup and ownerless-universe exceptions are listed above.

- **Direct admin-only operations:** company PUT/DELETE, POST company `/enrich`, `/retry`, and `/backfill-sector-size` all enforce `may_edit_shared()` before mutation. Non-admins receive 403, or 404 where visibility is checked first. Evidence: `careeros/server.py:company_api`, `enrich_company`, `retry_company`, `backfill_sector_size`, `may_edit_shared`, `shared_denied`; `careeros/users.py:is_admin`. Company GET remains intentionally shared.

- **Conditional admin-only branches:** `/resolve-review` blocks company creation for non-admins while allowing selection for their own job. Experience `/link-company` blocks `create`, but permits linking/unlinking existing companies. Job PUT and experience create/update block new vocabulary through `vocabulary_additions`, including legacy skills translation. Taxonomy and experience-form GETs are intentionally accessible; their `can_edit_shared` flag controls UI options, while writes independently enforce authorization. Evidence: the named handlers in `careeros/server.py`; `careeros/vault.py:validate_tags`, `unregistered_tags`, `save_experience`.

- **Indirect intake/enrichment writes:** tester intake, resolution, and background extraction cannot create companies or teach shared identifiers/name variants. `VaultOrganisationStore.save_organisation` rejects creation and makes existing-record writes no-ops when `shared=False`. Metadata, sources, contact promotion, and rollups are gated by session role or stored record owner. Tenant matching reads only the relevant owner’s jobs. Evidence: `careeros/org_store.py:VaultOrganisationStore.save_organisation`; `careeros/server.py:resolve_company`, `tenant_employer_names`, `find_company`, `apply_llm_update`, `enrich_job`; `careeros/enrich.py:contributes_to_shared`, `record_owner_scope`; `careeros/vault.py:save_job`, `save_watch_result`. Unscoped background reloads use IDs selected through an authorized initial lookup; client updates cannot transfer ownership.

- **Users, invites, and password-reset tokens:** no HTTP user-management or invite-creation/listing API is registered. Invitation acceptance always supplies `role=users.DEFAULT_ROLE`; payload role/email cannot select an administrator or another account. Reset targets come from the token record, not submitted user IDs. Tokens use random 32-byte values, hashed storage paths, expiration, and locked single-use consumption. Reset changes only its account and bumps its session epoch. User records/password hashes are not returned by these handlers. Evidence: `careeros/server.py:create_app`, `accept_invite`, `reset_password`, `login`; `careeros/invites.py:accept`; `careeros/password_reset.py:complete_reset`; `careeros/tokens.py:new_token`, `storage_path`, `consume`; `careeros/users.py:session_user`. An invited tester has the same restricted API access as any other tester; there is no separate admin page whose API bypasses these checks.

- **Unauthenticated routing and bypass shapes:** `require_login` exempts exact endpoint names, not path prefixes. The `/api/` prefix only selects JSON 401 versus login redirect. Case/trailing-slash variants do not create a new exempt endpoint. The gate has no method exemption; automatic OPTIONS does not execute mutation handlers. Public endpoints are exactly login, health, static/assets, invite acceptance, forgot-password, and reset-password. Health returns only `ok=True`; assets use fixed directories through `send_from_directory`. Evidence: `careeros/server.py:PUBLIC_ENDPOINTS`, `require_login`, `create_app`, `health`. HEAD’s mutation behavior is reported separately.

- **Exports and remaining storage kinds:** the complete route registration contains no private-record export/download endpoint or generic vault-file reader. ID counters/reservations, mail counts, rate-limit windows, and the signing key have no response endpoint exposing their contents. Evidence: `careeros/server.py:create_app` and registered handlers; `careeros/vault.py:_allocate`, `reserve_id`; `careeros/mail.py:sent_today`; `careeros/ratelimit.py:register`; `careeros/users.py:secret_key`.
